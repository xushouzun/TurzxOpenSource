# TURZX 3.5인치 시리얼 디스플레이 프로토콜

이 문서는 3.5인치 시리얼 디스플레이(`1A86:5722`)의 시리얼 프로토콜을 설명합니다. 이 장치는 WinUSB/Win207 장치가 아닙니다. Studio가 호스트에서 테마를 렌더링하고, 재생 시작 시 RGB565 전체 프레임을 한 번 전송한 뒤 변경된 영역만 CH340 시리얼로 전송합니다.

프로토콜은 단방향입니다. Studio는 응답을 읽지 않으므로, 시리얼 쓰기 성공은 Windows가 데이터를 받아들였다는 것만 의미합니다.

## 장치 및 시리얼 포트

- USB VID:PID는 `1A86:5722`이며 USB 인스턴스 이름에 `USB35INCH`가 포함됩니다. Studio는 해당 인스턴스의 활성 `COM` 포트를 찾습니다.
- 시리얼 설정은 115200 bps, 데이터 8비트, 패리티 없음, 정지 비트 1, 흐름 제어 없음입니다. DTR과 RTS를 사용합니다.
- 장치 캔버스는 480 × 320입니다. 테마는 480 × 320 또는 320 × 480 캔버스를 사용할 수 있습니다.
- 재생 시작과 방향 변경 시 전체 프레임을 전송합니다. 재생 중에는 약 1초마다 변경된 영역만 갱신합니다.

## 레지스터 패킷

각 전송은 6바이트 헤더로 시작합니다. X, Y, EndX, EndY는 10비트(0~1023)이고 레지스터는 1바이트입니다.

| 바이트 | 내용 |
| --- | --- |
| 0 | X의 9–2비트 |
| 1 | 7–6비트는 X의 1–0비트, 5–0비트는 Y의 9–4비트 |
| 2 | 7–4비트는 Y의 3–0비트, 3–0비트는 EndX의 9–6비트 |
| 3 | 7–2비트는 EndX의 5–0비트, 1–0비트는 EndY의 9–8비트 |
| 4 | EndY의 7–0비트 |
| 5 | 레지스터 번호 |

페이로드가 6바이트보다 길면 헤더가 페이로드 버퍼의 처음 6바이트를 덮어쓰므로 실제 데이터는 6바이트째부터 시작합니다. 6바이트 이하의 페이로드는 데이터를 담지 않으며 헤더만 전송합니다.

## 레지스터

| 레지스터 | 용도 | 필드 |
| --- | --- | --- |
| 255 | 연결 확인 | 좌표는 모두 0, 페이로드 없음 |
| 110 | 웨이크 / 백라이트 | X = 255 − 밝기 레벨. 레벨 0이 가장 어둡고 255가 가장 밝습니다. Studio는 웨이크 시 X = 0을 씁니다 |
| 109 | 웨이크 | 좌표는 모두 0, 페이로드 없음 |
| 122 | 미러 모드 | 16바이트 페이로드. 6바이트째가 모드(0 = 정상) |
| 121 | 방향 | 16바이트 페이로드. 6바이트째가 100 + 방향 타입(0–3), 7–8바이트가 너비, 9–10바이트가 높이이며 모두 빅 엔디언 |
| 197 | 프레임 시작 | 헤더의 X = 0, Y = 0, EndX = 너비 − 1, EndY = 높이 − 1. 이어서 RGB565 픽셀 전송 |

| 전송 | 바이트 |
| --- | --- |
| 연결 확인 | `00 00 00 00 00 FF` |
| 밝기 레벨 0(가장 어두움) | `3F C0 00 00 00 6E` |
| 밝기 레벨 255(가장 밝음) | `00 00 00 00 00 6E` |
| 정상 미러(16바이트) | `00 00 00 00 00 7A 00 00 00 00 00 00 00 00 00 00` |
| 가로 방향 2, 480 × 320(16바이트) | `00 00 00 00 00 79 66 01 E0 01 40 00 00 00 00 00` |
| 480 × 320 프레임 헤더 | `00 00 07 7D 3F C5`, 이어서 307,200바이트 픽셀 |

## 시작 순서

1. 시리얼 포트를 열고 약 100 ms 기다립니다.
2. 레지스터 255를 보냅니다.
3. 약 100 ms 기다린 뒤 레지스터 110과 109에 0을 씁니다.
4. 약 100 ms 기다린 뒤 미러 모드 0을 설정하고 방향을 설정합니다.
5. 약 500 ms 기다린 뒤 목표 밝기를 씁니다.
6. 레지스터 197 헤더를 보내고 약 10 ms 기다린 뒤 RGB565 프레임을 보내고 다시 약 10 ms 기다립니다.

지연 시간은 Studio의 현재 구현과 같습니다. 펌웨어에 따라 다른 타이밍도 허용될 수 있습니다.

## 방향

타입 0–3은 펌웨어의 네 방향에 대응합니다. 가로 테마는 기본으로 타입 2를, 반전 시 타입 3을 사용합니다. 세로 테마는 타입 0과 1을 사용합니다. Studio는 이 디스플레이에서 0°와 180°만 제공합니다.

## 프레임 데이터

픽셀은 RGB565이며 위에서 아래로, 왼쪽에서 오른쪽으로 배치되고 행 사이에 패딩이 없습니다. 각 픽셀은 2바이트이고 하위 바이트가 먼저입니다(리틀 엔디언). 480 × 320 한 프레임은 307,200바이트입니다. 115200 8N1에서 한 프레임 전송에 약 27초가 걸리므로 실시간 갱신에서는 변경된 영역만 전송합니다. 이 인터페이스는 실시간 동영상에는 적합하지 않습니다.

## 테마 파일

- 테마는 원래 3.5인치 디스플레이 도구가 생성하는 `.data` 파일입니다. .NET BinaryFormatter(NRBF) 직렬화 스트림이며 루트 개체는 `usb_hid.ThemeConfig`입니다.
- 파일에는 배경 PNG, 선택적 OSD 이미지, 텍스트 그룹, 막대, 원호, 팁 항목이 저장됩니다. `isLanscape`는 원본 파일의 표기를 유지합니다.
- 배경 캔버스는 480 × 320 또는 320 × 480이어야 하며 다른 크기는 거부됩니다.
- Studio는 이 형식을 읽기만 하며 다시 쓰지 않습니다. 테마 생성이나 편집에는 원래 도구를 사용하십시오.
- 텍스트, 막대, 원호, 이미지는 Studio가 호스트에서 렌더링합니다. 이름이 있는 지표는 시뮬레이션 모의 값을 사용하고, 이름이 없거나 사용자 정의 텍스트는 테마 값 또는 자리 표시자 샘플 값을 사용합니다. 실시간 센서 값은 읽지 않습니다.
- Studio에는 기본 테마 8개가 포함되어 있습니다(가로 480 × 320 6개, 세로 320 × 480 2개).

## 제한

- Studio는 읽기 채널, 응답, 재시도를 사용하지 않습니다. 시리얼 쓰기 오류만 전송 결과를 알려 줍니다.
- 암호화나 명령 키가 없습니다.
- 이 인터페이스는 장치 내 저장소, H.264, 레이어, 시계, 데스크톱 모드를 제공하지 않습니다.
- 한 번에 하나의 영역 또는 전체 프레임만 전송하며 교차 전송하지 마세요.

장치 인식과 Studio의 밝기·방향 조작은 [호환성 기록](compatibility.ko.md)을 참고하세요.
