# TURZX Win207 デバイスコマンドリファレンス

本プロジェクトが実装する Win207 のホスト側プロトコルを説明します。コマンドの対応状況はモデルとファームウェアのバージョンによって異なります。表のコマンド名は英語の大文字スネークケースで、読み取りは `GET_`、設定は `SET_`、転送は `WRITE_` で始まります。デバイスはコマンド番号とチャネルで要求を識別します。

オフセットは 0 から始まり、範囲には両端を含みます。`u8` は 1 バイト符号なし整数、`u16be` と `u32be` は 2 バイトと 4 バイトのビッグエンディアン符号なし整数、`u32le` は 4 バイトのリトルエンディアン符号なし整数です。ヘッダーは暗号化前の 500 バイトの平文ヘッダー、応答は IN エンドポイントから読み取った生のバイト列を指します。暗号化チャネルの番号は 10 進数、RAW チャネルの番号は 16 進数で表記します。

## 接続と呼び出し

- Windows はデバイスドライバーが登録したインターフェイス GUID を使って列挙します。既定値は `DEE824EF-729B-4A0E-9C14-B7117D33A817` です。カスタムドライバーでは、Studio 設定ファイルの `InterfaceGuid` フィールドまたは CLI の `--interface-guid` で指定します。
- WinUSB の OUT エンドポイントは `0x01`、IN エンドポイントは `0x81` です。要求を 1 件送るごとに応答を読み取り、取り違えを防ぎます。Studio のタイムアウトは OUT 書き込みが 10000 ms、IN 読み取りが 5000 ms で、読み取りバッファーは 512 バイトです。ファームウェアは PNG などの大きなライブデータを合成する際に一時停止することがあります。
- 8 バイトのパケットキーは組み込み済みです。Studio、CLI、SDK で追加設定は不要です。SDK には独自の 8 バイトを直接渡すこともできます。
- 応答の解析前に応答の長さを確認します。ファームウェア、ストレージ、電源電圧の構造化応答では、別のコマンドの残存応答を誤って解析しないよう、Studio は応答のバイト 0 が要求番号と一致することも確認します。応答を受け取っても、デバイスでの実行成功を意味しません。コマンドによっては状態フィールドが追加されます。

## 暗号化チャネルのパケット

| 位置 | 内容 |
| --- | --- |
| 平文 0 | コマンド番号 |
| 平文 1 | 予約領域。0 を設定 |
| 平文 2–3 | 固定マーカー `1A 6D` |
| 平文 4–7 | セッション作成時のローカル日付の前日 0 時から現在の UTC までのミリ秒差の下位 32 ビット。リトルエンディアン |
| 平文 8–499 | コマンド引数。残りは 0 で埋める |
| USB 要求 0–503 | 500 バイトの平文を DES-CBC で暗号化し、PKCS#7 でパディング。IV とキーにはどちらもファームウェアのキーを使用 |
| USB 要求 504–509 | 0 を 6 バイト |
| USB 要求 510–511 | 固定末尾マーカー `A1 1A` |
| USB 要求 512 以降 | 任意の生ペイロード。メディアデータはヘッダーの暗号化対象外 |

DES-CBC は既存ファームウェアとの互換形式です。デバイス応答は平文です。コマンド 101、102、121 はペイロードのバイト数をビッグエンディアンで平文 8–11 に格納します。1 バイトの制御引数は通常、平文 8 に置きます。

## 汎用送受信インターフェイス

ヘッダーとペイロードは 10 進数または 16 進数で入力できます。通常の 10 進入力は空白区切りの 0～255 のバイト列です。101/102 のヘッダーはペイロード長、121 は `ブロック長 最終フラグ` を入力し、長さをビッグエンディアンに変換します。

38/42/98/99/110/113 は絶対 ASCII デバイスパスを直接入力し、長さフィールドと予約領域は自動で設定されます。形式の切り替えで入力は消去されます。ここにないコマンドは各コマンドの定義に従ってください。10 進数のヘッダー引数は、`39` では「バッファー容量 有効長 最終フラグ」、`51` では「年 月 日 時 分 秒 モード」の順に入力します。

コマンド 101（JPEG）、102（PNG）、40（小さいファイルの書き込み）ではローカルファイルを参照できます。Studio がバイト数を設定します。40 ではデバイス上の絶対 ASCII パスと 100 KiB 未満のファイルが必要です。ファイル選択後に送信を実行してください。

コマンド 121 の **H.264 を選択** では `.h264` または `.264` の背景動画を選択します。選択後もデバイスコマンド画面に留まるため、**メディア** を開いて再生を開始してください。動画のみを再生する場合は前景をクリアします。Studio がブロック分割とキュー制御を行います。

デバイス内のファイルは **詳細設定 → デバイス内メディア** から選択できます。`39` でもローカルファイルを選べます。先に `38` で対象ファイルを作成してください。空でない 1 MiB 以下のファイルを指定すると、Studio が 1 MiB のバッファーに補完し、有効長と最終フラグを設定します。`40` では既存のディレクトリを指定し、書き込み後に `98` でサイズを確認できます。

ローカルの JPEG と PNG は 1～950,000 バイトのファイルを使用します。

送信前に選択した機器の Studio 再生を停止してください。`99` を除く暗号化コマンドでは、応答がコマンド番号を返し、最小長を満たすことを確認します。古い応答は読み飛ばし、要求は再送しません。`99` はテキスト断片を 1 つ表示します。全体を読むには **詳細設定 → デバイス内メディア** で更新し、取得が完了したか確認してください。

Studio の **デバイスコマンド** で左の一覧からコマンドを選択します。右にはそのコマンドに必要な入力欄が表示されます。機器が対応する引数なしのコマンドはそのまま送信できます。入力欄が収まらない場合は右のフォームをスクロールしてください。送信ボタンと応答欄はフォームの下に固定されています。

右で番号やチャネルを変更すると、対応するプリセットがある場合は左の一覧で選択されます。右の説明とフォームが更新され、直前の引数と選択済みファイルはクリアされます。番号には 10 進数または `0x` で始まる 16 進数を使用できます。暗号化チャネルと RAW チャネルの番号は独立しています。例えば暗号化チャネルの `60` は向き、RAW チャネルの `0x60` は温度を取得します。

| 入力または戻り値 | 暗号化 Win207 | RAW チャネル |
| --- | --- | --- |
| コマンド番号 | 0～255。平文ヘッダーのオフセット 0 に書き込む | 0～255。要求のオフセット 0 に書き込む |
| 引数 | 平文ヘッダーのオフセット 8 から 0～492 バイト。残りは 0 で埋める | オフセット 1 から 0～63 バイト。残りは 0 で埋める |
| ペイロード | 任意。USB オフセット 512 から追加する。長さ、フラグなどのヘッダーフィールドはコマンド表に従って指定する | 個別のペイロードはなく、要求は固定 64 バイト |
| 戻り値 | IN エンドポイントから実際に返された全バイト。0 も保持し、512 バイトへのパディングは行わない | 左記と同じ |
| 応答なし、または転送失敗 | 空の応答や書き込み不足は I/O エラー。ドライバーエラーには操作名と Windows エラーコードが含まれる | 左記と同じ |

応答欄には 16 進数のオフセットとバイト値、印字可能な ASCII が表示されます。他の文字はドットで示します。応答番号、フィールドの位置、状態値は各コマンドを参照してください。実行結果は対応する機器状態や画面出力で確認します。

| 例 | チャネルと番号 | 引数 | 応答 |
| --- | --- | --- | --- |
| ファームウェアを取得 | 暗号化 10 | 空 | 応答長 ≥ 40 バイト、オフセット 0 = 10、8–39 = UTF-8 のバージョン文字列 |
| H.264 ブロックサイズを取得 | 暗号化 17 | 空 | 応答 ≥ 12 バイト、8–11 = ビッグエンディアンのブロック長。0 は既定値 |
| デバイスの明るさを 60 に設定 | 暗号化 14 | `3C` | 共通の成功コードは未定義。機種ごとの明るさ上限を適用するには SDK の `SetBrightness` を使用する |
| 冷却温度を取得 | RAW 0x60（SDK） | 空 | 応答 ≥ 3 バイト、1 と 2 = ポンプとファンの温度（°C） |

```csharp
byte[] firmware = screen.ExchangeCommand(10);
byte[] temperatures = screen.ExchangeRawCommand(0x60);
Console.WriteLine(Convert.ToHexString(firmware));
Console.WriteLine(Convert.ToHexString(temperatures));
```

**コード例**で生成した例は、デバイスを開く前にモデルとパラメーターの範囲を確認します。削除の例は、送信前に `DELETE` の入力が必要です。

## Windows デスクトップモードと USB 副画面モード

対応機種では、**デバイスコマンド** で `150` を送信します。`150` は次回起動時のモードを設定するだけです。応答後、Studio がすぐに再起動するか確認します。手動で `11` を送信することもできます。再起動して Windows デスクトップモードに入ると、WinUSB インターフェイスが消え、デスクトップモードの HID インターフェイス（`1A86:AD11`）が現れます。

Studio から画像と動画を送信できる状態に戻すには、**デバイスコマンド** の左の一覧でコマンド `150` の直後にある `SWITCH_TO_MONITOR_MODE` を選択します。この HID 操作に Win207 の番号や引数の入力は不要です。Studio の USB デバイス一覧が空でも操作できます。右の詳細画面でデスクトップモード機器を更新し、シリアル番号で対象を選び、**USB副画面に戻す** をクリックします。Studio は HID レポートを 1 回送信し、同じシリアル番号の WinUSB インターフェイスを最大 25 秒待ちます。

デスクトップモードで Windows が画面をモニターとして認識するには、同梱の TURZX ディスプレイドライバーが必要です。未インストールの場合は **詳細設定** ページの「デスクトップモード ドライバー」欄で **デスクトップモード ドライバーをインストール** をクリックし、管理者の確認ダイアログで許可します。インストールは 1 台につき 1 回です。削除する場合は、同じ欄で **デスクトップモード ドライバーをアンインストール** をクリックします。

12.3 インチ（`1CBE:0123`）のコマンド画面では、RAW チャネルと暗号化コマンド `12`、`51`、`52`、`61`、`62`、`125`、`251`、`252` が無効です。消灯するには `14` に 10 進数の `0` を指定して送信します。この画面で `14` はデバイス値 0～80、`13` は `0` を受け付けます。他の向きは **メディア** で選ぶと Studio がフレームを回転します。

標準の円形ディスプレイ（PID `0021`）は Windows デスクトップモードに対応していません。RAW の LED・温度・回転数コマンドは専用コントローラー `0416:8061`、`0416:8052` 用で、Studio は画面にこれらのコマンドを送信しません。暗号化番号 61 と 62 はプロトコル参照用です。

通常の動画転送は次の順序で行います。既存の再生と時計レイヤーを停止し（123、52）、フレームレートを設定し（15）、ブロックサイズを読み取り（17）、キューの深さが 1 以下になるまで待ってから Annex B データをブロック単位で送信します（121）。ファイル入力ではブロック間に約 30 ms 待機します。ライブ入力は小さめのブロックで送信し、短時間待ってフレームをまとめることで、ブロックごとの応答待ちを減らします。キューの深さが 3 を超えると、SDK は 2 以下になるまで待ってから続行します。ホストが送信を終了した後も、デバイスは受信済みのブロックを再生し続けます。

デバイスがレイヤー合成に対応している場合、同じセッションで 102（PNG 前景）と 121（H.264 背景）を交互に送信できます。1 組の要求と応答が完了してから次を送ります。122 の同期拡張は、64 ビットの同期時刻（ms）をヘッダー 8–15 に、32 ビットの総フレーム数を 16–19 にビッグエンディアンで格納します。Studio は通常の照会のみを使用し、この拡張は使用しません。

## RAW チャネル

RAW チャネルは同じエンドポイントを使います。要求は DES パケットを使わない 64 バイトのバッファーで、コマンド番号はオフセット 0 に置きます。

| 番号 | 名前 | 要求と応答 | Studio の操作画面 |
| --- | --- | --- | --- |
| 0x11 | WRITE_LED_PIXEL_BLOCK | 要求 1 は u8 の LED 開始インデックス。RGB データは 4 以降。対応する分割例ではインデックス 0、15、30 に対して最大 45、45、15 バイトを配置し、残りを 0 で埋める | リファレンス |
| 0x60 | GET_COOLING_TEMPERATURES | 要求 1–63 を 0 で埋める。応答 ≥ 3 バイト。1 と 2 はポンプとファンの温度 u8、単位は °C | リファレンス |
| 0x61 | SET_COOLING_SPEEDS | 要求 1–2 と 3–4 はポンプとファンの目標値を格納する u16be。5–63 は 0。対応する生値のフルスケールは 3500 | リファレンス |
| 0x62 | GET_COOLING_SPEEDS | 要求 1–63 を 0 で埋める。応答 ≥ 5 バイト。1–2 と 3–4 はポンプとファンの回転速度 u16be。換算はモデルに依存 | リファレンス |

## パケットと応答の例

以下はタイムスタンプを 1 ms に固定した暗号化前のヘッダーです。各ヘッダーを 0 で 500 バイトまで埋め、「暗号化チャネルパケット」の手順で暗号化します。

| 操作 | 平文ヘッダーの先頭バイト | 説明 |
| --- | --- | --- |
| バージョンを取得 | `0A 00 1A 6D 01 00 00 00` | 10 進数 10 = 0A。引数はすべて 0 |
| 明るさを 60 に設定 | `0E 00 1A 6D 01 00 00 00 3C` | オフセット 8 の 3C は 10 進数 60 |
| 180° 回転 | `0D 00 1A 6D 01 00 00 00 02` | オフセット 8 は向きのコード 2 |
| 1024 バイトの PNG を送信 | `66 00 1A 6D 01 00 00 00 00 00 04 00` | 長さはビッグエンディアン。USB 要求は合計 1536 バイト |
| 512 バイトの最終 H.264 ブロックを送信 | `79 00 1A 6D 01 00 00 00 00 00 02 00 01` | オフセット 12 は最終ブロックフラグ |

応答の解析例

- 17 の応答の 8–11 が `00 03 18 00` の場合、H.264 ブロック長は 202752 バイト（198 KiB）です。
- 100 の応答の 8–11 が `00 10 00 00` の場合、SD の合計容量は 4096 KiB です。このフィールドはリトルエンディアンです。
- RAW チャネルの温度照会では `60` に 63 バイトの 0 を続けます。応答のオフセット 1 と 2 が `23 28` なら、温度はそれぞれ 35 °C と 40 °C です。
- RAW チャネルの回転速度応答のオフセット 1–4 が `06 D6 03 E8` なら、生値は 1750 と 1000 です。

## 実行例

以下の CLI コマンドはソースリポジトリのルートから実行します。最初に `list` でデバイスのインデックスを取得します。SDK ZIP からデバイスを列挙するには `dotnet run --project examples/SdkDiscover` を実行します。

```powershell
dotnet run --project src/TURZX.WinUsbDisplay.Cli -- list
dotnet run --project src/TURZX.WinUsbDisplay.Cli -- info 0
dotnet run --project src/TURZX.WinUsbDisplay.Cli -- brightness 0 60
dotnet run --project src/TURZX.WinUsbDisplay.Cli -- image 0 artwork.png
dotnet run --project src/TURZX.WinUsbDisplay.Cli -- video 0 motion.mp4 24 --loop
dotnet run --project src/TURZX.WinUsbDisplay.Cli -- stop 0
```

SDK では 1 つのセッションで複数のデバイスメソッドを呼び出せます。診断メソッドは生の応答を返します。上記の表に従って解釈してください。

```csharp
using TURZX.WinUsbDisplay;

var devices = DisplayDevice.Discover(DisplaySettings.InterfaceGuid);
if (devices.Count == 0)
    throw new InvalidOperationException("No Win207 display found.");
using var screen = devices[0].Open(DisplaySettings.ReadCommandKey());
Console.WriteLine(screen.ReadFirmwareVersion());
screen.SetRotation(2);
byte[] status = screen.ReadDiagnostic(60);
if (status.Length >= 10)
    Console.WriteLine($"orientation {status[8]}, sensor {status[9]}");
byte[] temperatures = screen.ReadDiagnostic(0x60, raw: true);
```

参考資料は [Microsoft の WinUSB ガイド](https://learn.microsoft.com/en-us/windows-hardware/drivers/usbcon/using-winusb-api-to-communicate-with-a-usb-device) と [FFmpeg のフォーマット文書](https://ffmpeg.org/ffmpeg-formats.html) を参照してください。

デバイス制御 DLL を直接参照するためのプロジェクト設定と完全な例は、[DLL 開発ガイド](developer-guide.ja.md) を参照してください。
