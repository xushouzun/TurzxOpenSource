# TURZX Win207 设备指令技术说明

本文记录本项目实现的 Win207 主机端协议。指令是否可用取决于型号和固件版本。指令名称采用英文大写蛇形命名。读取用 `GET_`，配置用 `SET_`，传输用 `WRITE_`。设备按指令编号和通道识别请求。

偏移从 0 开始，范围含首尾。`u8` 是 1 字节无符号整数，`u16be`、`u32be` 是 2、4 字节大端无符号整数，`u32le` 是 4 字节小端无符号整数。「头」指加密前的 500 字节明文头，「应答」指从 IN 端点读取的原始字节。加密通道编号以十进制表示，裸通道编号以十六进制表示。

## 连接和调用

- Windows 通过设备驱动注册的接口 GUID 枚举。默认 GUID 为 `DEE824EF-729B-4A0E-9C14-B7117D33A817`。自定义驱动可在 Studio 设置文件的 `InterfaceGuid` 字段或 CLI 的 `--interface-guid` 参数中指定。
- WinUSB OUT 端点为 `0x01`，IN 端点为 `0x81`。每次先发送一条请求，再读取应答，避免指令错配。Studio 的 OUT 写超时 10000 毫秒、IN 读超时 5000 毫秒，读取缓冲区 512 字节。实时 PNG 等大块载荷在固件合成期间会短暂停顿。
- 8 字节命令密钥已内置，Studio、CLI 和 SDK 无需额外配置。SDK 仍可直接传入自定义 8 字节密钥。
- 解析应答前先检查应答长度。Studio 对固件、存储和供电的结构化查询同时检查应答首字节是否回显请求编号，避免解析其他指令留下的应答。收到应答不代表设备已成功执行，某些指令还另有状态字段。

## 加密通道封包

| 位置 | 内容 |
| --- | --- |
| 明文 0 | 指令编号 |
| 明文 1 | 保留为 0 |
| 明文 2–3 | 固定标识 `1A 6D` |
| 明文 4–7 | 当前 UTC 时间减去会话创建时确定的本地昨天零点，取毫秒差的低 32 位，小端 |
| 明文 8–499 | 指令参数，空余部分填 0 |
| USB 请求 0–503 | 500 字节明文以 DES-CBC 加密，PKCS#7 填充。IV 和密钥均为固件参数 |
| USB 请求 504–509 | 六个 0 字节 |
| USB 请求 510–511 | 固定尾标 `A1 1A` |
| USB 请求 512 起 | 可选原始载荷。媒体载荷不参与头部加密 |

DES-CBC 是现有固件的兼容格式。设备应答保持明文。命令 101、102、121 的明文 8–11 存载荷字节数（大端）。单字节控制参数一般放在明文 8。

## 通用收发接口

在 **设备指令** 页，头部参数和载荷均可选择十进制或十六进制。普通十进制输入按空格分隔的 0–255 字节解释；101/102 的头部十进制数是完整载荷长度，121 输入“块长度 末块标志”，自动生成大端字段。

38/42/98/99/110/113 默认使用设备路径输入，直接填写绝对 ASCII 路径，由程序填写长度字段和保留字节。切换格式会清空对应输入，避免按另一进制误发。未列出的指令请按对应指令定义填写。十进制头部参数 `39` 按“缓冲容量 有效长度 末块标志”输入，`51` 按“年 月 日 时 分 秒 模式”输入。

指令 101（JPEG）、102（PNG）和 40（小文件写入）支持浏览本地文件。Studio 自动填写字节长度；40 还需要填写设备上的绝对 ASCII 目标路径，文件须小于 100 KiB。选中文件后仍需手动发送。

指令 121 的 **浏览 H.264** 用于选择 `.h264` 或 `.264` 背景视频。选好后仍停留在设备指令页，需要到 **媒体** 页开始播放；只播放视频时清空前景。分块和缓冲队列由 Studio 负责。

指令 39 也可选择本地文件，但需先用 38 创建目标文件。文件须非空且不超过 1 MiB，Studio 自动补足 1 MiB 缓冲、填写有效长度并标记末块。40 要求目标目录已存在，写入后可用 98 核对文件大小。

已存入设备的文件可在 **高级控制 → 设备内媒体** 中选择。本地 JPEG 和 PNG 须非空且不超过 950,000 字节。

发送前请停止所选设备的 Studio 播放。除 `99` 外，加密通道会校验应答首字节是否回显指令编号，并检查最短长度；遇到残留应答继续读取，不重发请求。`99` 在指令页只显示一段文本应答，完整目录请到 **高级控制 → 设备内媒体** 刷新，并检查结果是否完整。

在 Studio 的 **设备指令** 中，从左侧列表选择指令，右侧只显示该指令需要的输入项。可用的无参数指令可直接发送；参数较多时可滚动右侧表单，发送按钮和应答区固定在下方。

也可在右侧直接更改编号或通道：有对应预设时左侧会选中它，右侧同步更新说明和表单，并清空上一条指令的参数与所选文件；没有对应预设时列表不选中任何指令。编号可用十进制或 `0x` 前缀十六进制表示。加密通道和裸通道的编号彼此独立，例如加密十进制 `60` 查询方向，裸十六进制 `0x60` 查询温度。

| 输入或返回 | 加密 Win207 | 裸通道 |
| --- | --- | --- |
| 指令编号 | 0–255，写入明文头偏移 0 | 0–255，写入请求偏移 0 |
| 参数 | 0–492 字节，从明文头偏移 8 写入，余下填零 | 0–63 字节，从偏移 1 写入，余下填零 |

| 示例 | 通道与编号 | 参数 | 读回值 |
| --- | --- | --- | --- |
| 查询固件 | 加密 10 | 留空 | 检查应答长度至少 40，偏移 0 为 10，8–39 为 UTF-8 版本文本 |

```csharp
byte[] firmware = screen.ExchangeCommand(10);

Console.WriteLine(Convert.ToHexString(firmware));
Console.WriteLine(Convert.ToHexString(temperatures));
```

## Windows 桌面模式与副屏模式

在支持的屏幕上，先在 **设备指令** 中发送 `150`。`150` 只设置下次启动进入 Windows 桌面模式；设备应答后 Studio 会询问是否立即重启，也可以手动发送 `11`。设备重启并进入桌面模式后，WinUSB 接口会消失，桌面模式 HID 接口（`1A86:AD11`）会出现。

要恢复 Studio 图片和视频输出，在 **设备指令** 左侧列表找到 `150`，选择紧随其后的 `SWITCH_TO_MONITOR_MODE`。此项通过 HID 报告切回副屏模式，无需填写 Win207 指令编号或参数。即使 Studio 的 USB 副屏列表为空，仍可打开右侧回切面板，刷新桌面模式设备，按序列号选择目标，再点击 **切回副屏模式**。Studio 只发送一份 HID 报告，等待同序列号的 WinUSB 接口重新出现，最长 25 秒。

桌面模式需要随包提供的 TURZX 显示驱动，Windows 才能将屏幕识别为显示器。未安装时，在 **高级控制** 页的「桌面模式驱动」区域点击 **安装桌面模式驱动**，并在管理员提示中确认；每台机器安装一次即可。需要移除驱动时，可在同一区域点击 **卸载桌面模式驱动**。

12.3 寸屏（`1CBE:0123`）的指令收发禁用裸通道及加密指令 `12`、`51`、`52`、`61`、`62`、`125`、`251`、`252`。熄屏可单独发送 `14`，参数填十进制 `0`。指令页中 `14` 的设备值范围为 0–80，`13` 只接受 `0`，其余方向在 **媒体** 页设置，由主机旋转画面。

普通圆屏（PID `0021`）不提供 Windows 桌面模式。裸通道的灯珠、温度和转速指令用于独立控制器 `0416:8061`、`0416:8052`，Studio 不向屏幕发送这些指令。加密编号 61 和 62 仅供协议参考。

普通视频传输按以下顺序进行：停止已有播放和时钟层（123、52），设置帧率（15），读取块大小（17），等待队列深度降到 1 或更低，再逐块发送 Annex B 数据（121）。文件输入每块之间等待约 30 毫秒；实时输入按较小块发送，并短暂等待以合并帧，降低单块应答开销。队列深度大于 3 时，SDK 会等待其降到 2 或更低再继续。主机停止发送后，设备会继续播放已接收的剩余块。

设备支持图层叠加时，可在同一会话中交替发送 102（PNG 前景）和 121（H.264 背景），每完成一组请求和应答后再发下一组。122 的同步扩展把 64 位同步时间（毫秒）放在头 8–15，把 32 位总帧数放在头 16–19，均为大端。Studio 只发送普通查询，不使用该扩展。

## 裸通道

裸通道使用同一端点，但请求是 64 字节缓冲，不带 DES 封包。编号放在请求 0。

| 编号 | 名称 | 请求和应答 | Studio 入口 |
| --- | --- | --- | --- |
| 0x11 | WRITE_LED_PIXEL_BLOCK | 请求 1 为 u8 LED 起始索引，RGB 数据从 4 起。一种分块布局使用索引 0、15、30，对应数据最多 45、45、15 字节，余下填 0 | 仅参考 |
| 0x60 | GET_COOLING_TEMPERATURES | 请求 1–63 填 0。应答至少 3 字节，1、2 是泵和风扇温度 u8，单位 °C | 仅参考 |
| 0x61 | SET_COOLING_SPEEDS | 请求 1–2 和 3–4 分别为 u16be 泵与风扇目标值，5–63 填 0。兼容实现采用 3500 作为原始满量程 | 仅参考 |
| 0x62 | GET_COOLING_SPEEDS | 请求 1–63 填 0。应答至少 5 字节，1–2、3–4 为泵和风扇转速 u16be。数值换算以型号为准 | 仅参考 |

## 封包和应答示例

以下为加密前头部，时间戳固定为 1 毫秒。每个加密头补零至 500 字节，再按“加密通道封包”一节的规则加密。

| 操作 | 明文头起始字节 | 解释 |
| --- | --- | --- |
| 读取版本 | `0A 00 1A 6D 01 00 00 00` | 十进制 10 对应 0A，参数均为 0 |
| 设置亮度 60 | `0E 00 1A 6D 01 00 00 00 3C` | 偏移 8 的 3C 是十进制 60 |
| 旋转 180° | `0D 00 1A 6D 01 00 00 00 02` | 偏移 8 为方向代码 2 |
| 发送 1024 字节 PNG | `66 00 1A 6D 01 00 00 00 00 00 04 00` | 长度按大端写入，USB 请求共 1536 字节 |
| 发送 512 字节 H.264 末块 | `79 00 1A 6D 01 00 00 00 00 00 02 00 01` | 偏移 12 为末块标志 |

应答解码示例：

- 17 应答 8–11 为 `00 03 18 00` 时，H.264 块长为 202752 字节，即 198 KiB。
- 100 应答 8–11 为 `00 10 00 00` 时，SD 总容量字段为 4096 KiB。此字段为小端。
- 裸通道温度查询发送 `60` 加 63 个零字节。应答偏移 1、2 若为 `23 28`，对应 35 °C、40 °C。
- 裸通道转速应答偏移 1–4 若为 `06 D6 03 E8`，对应原始值 1750 和 1000。

## 可直接调用的示例

在源码仓库根目录运行以下 CLI 命令。先用 `list` 获取设备索引。SDK ZIP 中可运行 `dotnet run --project examples/SdkDiscover` 枚举设备。

```powershell
dotnet run --project src/TURZX.WinUsbDisplay.Cli -- list
dotnet run --project src/TURZX.WinUsbDisplay.Cli -- info 0
dotnet run --project src/TURZX.WinUsbDisplay.Cli -- brightness 0 60
dotnet run --project src/TURZX.WinUsbDisplay.Cli -- image 0 artwork.png
dotnet run --project src/TURZX.WinUsbDisplay.Cli -- video 0 motion.mp4 24 --loop
dotnet run --project src/TURZX.WinUsbDisplay.Cli -- stop 0
```

SDK 可在同一个会话中调用设备方法。诊断返回原始应答，按指令表解释。

```csharp
using TURZX.WinUsbDisplay;

var devices = DisplayDevice.Discover(DisplaySettings.InterfaceGuid);
if (devices.Count == 0)
    throw new InvalidOperationException("未找到 Win207 屏幕。");
using var screen = devices[0].Open(DisplaySettings.ReadCommandKey());
Console.WriteLine(screen.ReadFirmwareVersion());
screen.SetRotation(2);
byte[] status = screen.ReadDiagnostic(60);
if (status.Length >= 10)
    Console.WriteLine($"方向 {status[8]}，传感器 {status[9]}");
byte[] temperatures = screen.ReadDiagnostic(0x60, raw: true);
```
