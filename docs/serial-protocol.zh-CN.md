# TURZX 3.5 寸串口屏协议

本文说明 3.5 寸串口屏（`1A86:5722`）使用的串口协议。该屏不属于 WinUSB/Win207 设备：Studio 在本机渲染 JSON 主题，再通过 CH340 串口发送一整帧 RGB565 画面。

协议是单向的，Studio 不读取应答。串口写入成功只表示 Windows 接受了数据，不能证明设备已显示。

## 设备和串口

- USB VID:PID 为 `1A86:5722`，USB 实例名包含 `USB35INCH`。Studio 按该实例查找处于活动状态的 `COM` 口。
- 串口参数：115200 波特率、8 数据位、无校验、1 停止位、无流控；DTR 和 RTS 使能。
- 设备画布为 480 × 320。主题可使用 480 × 320 或 320 × 480 画布。
- 只在开始播放、切换主题或切换方向时发送整帧，不做连续推流。

## 寄存器包

每次传输以 6 字节头开始。X、Y、EndX、EndY 均为 10 位（0–1023），寄存器号为 1 字节。

| 字节 | 内容 |
| --- | --- |
| 0 | X 的 9–2 位 |
| 1 | 7–6 位为 X 的 1–0 位；5–0 位为 Y 的 9–4 位 |
| 2 | 7–4 位为 Y 的 3–0 位；3–0 位为 EndX 的 9–6 位 |
| 3 | 7–2 位为 EndX 的 5–0 位；1–0 位为 EndY 的 9–8 位 |
| 4 | EndY 的 7–0 位 |
| 5 | 寄存器号 |

若传输带超过 6 字节的载荷，载荷缓冲的前 6 字节会被头覆盖，有效字段从第 6 字节开始。6 字节及以下的载荷会被忽略，只发送头。

## 寄存器

| 寄存器 | 用途 | 字段 |
| --- | --- | --- |
| 255 | 连接探测 | 坐标全 0，无载荷 |
| 110 | 唤醒 / 背光 | X = 255 − 亮度等级。等级 0 最暗，255 最亮。Studio 唤醒时将 X 写为 0 |
| 109 | 唤醒 | 坐标全 0，无载荷 |
| 122 | 镜像模式 | 16 字节载荷；第 6 字节为模式，0 表示正常 |
| 121 | 方向 | 16 字节载荷；第 6 字节为 100 + 方向类型（0–3），第 7–8 字节为宽、第 9–10 字节为高，均为大端 |
| 197 | 帧起始 | 头中 X = 0、Y = 0、EndX = 宽 − 1、EndY = 高 − 1；随后是 RGB565 像素 |

| 传输 | 字节 |
| --- | --- |
| 探测 | `00 00 00 00 00 FF` |
| 亮度等级 0（最暗） | `3F C0 00 00 00 6E` |
| 亮度等级 255（最亮） | `00 00 00 00 00 6E` |
| 正常镜像（16 字节） | `00 00 00 00 00 7A 00 00 00 00 00 00 00 00 00 00` |
| 横屏方向 2，480 × 320（16 字节） | `00 00 00 00 00 79 66 01 E0 01 40 00 00 00 00 00` |
| 480 × 320 帧头 | `00 00 07 7D 3F C5`，随后为 307,200 字节像素 |

## 启动顺序

1. 打开串口，等待约 100 毫秒。
2. 发送寄存器 255。
3. 等待约 100 毫秒，向寄存器 110 和 109 各写 0。
4. 等待约 100 毫秒，设置镜像模式 0，再设置方向。
5. 等待约 500 毫秒，写入目标亮度。
6. 发送寄存器 197 帧头，等待约 10 毫秒，发送 RGB565 帧，再等待约 10 毫秒。

上述延时与 Studio 当前实现一致；固件也可能接受其他时序。

## 方向

类型 0–3 对应固件的四种方向。横屏主题默认用类型 2，反向时用类型 3；竖屏主题用类型 0 和类型 1。Studio 对该串口屏只提供 0° 和 180°。

## 帧数据

像素为 RGB565，按从上到下、从左到右排列，行间无填充。每个像素 2 字节，低字节在前（小端）。480 × 320 一帧为 307,200 字节。115200 8N1 下发送整帧约需 27 秒，因此该接口只适合静态主题画面，不适合实时视频。

## 主题文件

- Studio 只读取 JSON 格式的 `.data`，旧版二进制 `.data` 会被拒绝。
- `backImg` 必填，内容为 base64 PNG；默认主题将其放在 `backImg.png` 下。可选字段包括 `osdImg`、`osdWithFontBack`、`groupList`、`barList`、`archList` 和 `tipList`。
- `isLanscape` 保留原主题文件的拼写。画布必须为 480 × 320 或 320 × 480。
- 文字、进度条、圆弧和图片均由 Studio 在本机渲染，数值来自主题文件；条目文本为空时使用占位示例值，不读取实时传感器。
- Studio 内置三个横屏默认主题，均为 480 × 320。

## 限制

- Studio 不使用读取通道、应答或重试；串口写入错误是唯一的传输反馈。
- 无加密，无命令密钥。
- 该接口不提供设备内存储、H.264、图层、时钟或桌面模式。
- 同一时间只传输一整帧，不要交叉发送多帧。

设备识别、Studio 中的亮度和方向操作见[设备兼容性](compatibility.zh-CN.md)。
