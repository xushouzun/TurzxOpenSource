# TURZX Win207 장치 명령 참조

이 문서는 이 프로젝트가 구현하는 Win207 호스트 측 프로토콜을 설명합니다. 명령 지원 여부는 모델과 펌웨어 버전에 따라 다릅니다. 표의 명령 이름은 영문 대문자 스네이크 표기법을 사용하며, 읽기는 `GET_`, 설정은 `SET_`, 전송은 `WRITE_`로 시작합니다. 장치는 명령 번호와 채널로 요청을 식별합니다.

오프셋은 0부터 시작하며 범위는 양 끝을 포함합니다. `u8`은 1바이트 부호 없는 정수, `u16be`와 `u32be`는 각각 2바이트와 4바이트 빅 엔디언 부호 없는 정수, `u32le`는 4바이트 리틀 엔디언 부호 없는 정수입니다. 헤더는 암호화 전 500바이트 평문 헤더이며, 응답은 IN 엔드포인트에서 실제로 읽은 바이트입니다. 암호화 채널 번호는 10진수, 원시 채널 번호는 16진수로 표시합니다.

## 연결 및 호출

- Windows는 장치 드라이버에 등록된 인터페이스 GUID로 장치를 열거합니다. 확인된 기본값은 `DEE824EF-729B-4A0E-9C14-B7117D33A817`이며 `WINUSB_DISPLAY_INTERFACE_GUID`로 재정의할 수 있습니다.
- WinUSB OUT 엔드포인트는 `0x01`, IN 엔드포인트는 `0x81`입니다. 명령 간 응답이 섞이지 않도록 요청을 한 건 보낼 때마다 응답을 읽으세요. Studio의 제한 시간은 OUT 쓰기 10000 ms, IN 읽기 5000 ms입니다. PNG 등 큰 실시간 페이로드는 펌웨어가 배경을 합성하는 동안 잠시 멈출 수 있습니다. 제한 시간이 너무 짧으면 전송이 중단되어 엔드포인트가 멈추거나 지연된 응답을 놓칠 수 있습니다. 일반 제어 응답은 빠르며 이 시간은 대기 상한입니다. 읽기 버퍼는 512바이트입니다.
- 펌웨어 유지 관리자에게서 8바이트 패킷 키를 받습니다. Windows에서 Studio 또는 CLI를 시작하기 전에 해당 16자리 16진수 문자열을 `WINUSB_DISPLAY_COMMAND_KEY`에 설정하세요. SDK에 8바이트를 직접 전달할 수도 있습니다.
- 응답을 분석하기 전에 실제 길이를 확인하세요. 펌웨어, 저장소 및 공급 전압의 구조화된 응답을 읽을 때 Studio는 다른 명령의 남은 응답을 잘못 분석하지 않도록 응답 바이트 0이 요청 번호와 일치하는지도 확인합니다. USB 응답 수신과 장치 실행 성공은 별도로 판단합니다. 일부 명령에는 추가 응답 필드가 있습니다.

## 암호화 채널 패킷

| 위치 | 내용 |
| --- | --- |
| 평문 0 | 명령 번호 |
| 평문 1 | 예약됨. 0으로 설정 |
| 평문 2–3 | 고정 마커 `1A 6D` |
| 평문 4–7 | 현재 UTC 시각과 세션을 만들 때 기준으로 삼은 현지 어제 자정의 차이를 밀리초로 나타낸 값의 하위 32비트. 리틀 엔디언 |
| 평문 8–499 | 명령 매개 변수. 나머지는 0으로 채움 |
| USB 요청 0–503 | 500바이트 평문을 DES-CBC로 암호화하고 PKCS#7로 패딩. IV와 키에 모두 펌웨어 키를 사용 |
| USB 요청 504–509 | 0 바이트 6개 |
| USB 요청 510–511 | 고정 끝 마커 `A1 1A` |
| USB 요청 512 이후 | 선택적 원시 페이로드. 미디어 페이로드는 헤더 암호화 범위에서 제외됨 |

DES-CBC는 기존 펌웨어의 호환 형식입니다. 장치 응답은 평문입니다. 명령 101, 102, 121은 페이로드 바이트 수를 빅 엔디언으로 평문 8–11에 저장합니다. 1바이트 제어 매개 변수는 일반적으로 평문 8에 놓습니다.

## 범용 송수신 인터페이스

헤더 인자와 페이로드는 10진수 또는 16진수로 입력할 수 있습니다. 일반 10진수 입력은 공백으로 구분한 0~255 바이트입니다. 101/102의 헤더에는 전체 페이로드 길이를, 121에는 `블록길이 마지막표시`를 입력하며 길이는 빅 엔디언으로 변환됩니다. 38/42/98/99/110/113은 절대 ASCII 장치 경로를 직접 입력하면 길이와 예약 바이트를 자동 생성합니다. 형식을 바꾸면 해당 입력이 지워집니다. 미확인 형식은 각 명령 정의를 따릅니다. 10진수 헤더는 `39`에 ‘버퍼 용량 유효 길이 마지막 블록 플래그’, `51`에 ‘연 월 일 시 분 초 모드’ 순으로 입력합니다.

명령 101(JPEG), 102(PNG), 40(작은 파일 쓰기)에서는 로컬 파일을 선택할 수 있습니다. Studio가 바이트 길이를 채웁니다. 명령 40에는 장치의 절대 ASCII 대상 경로와 100 KiB 미만의 파일이 필요합니다. 파일을 고른 뒤 보내기를 눌러 전송하세요. 명령 121의 **H.264 찾아보기**는 `.h264` 또는 `.264`를 미디어 페이지의 배경으로 선택합니다. 플레이어가 블록 분할과 큐 간격을 처리합니다. 동영상만 재생하려면 전경을 지우세요. 장치에 저장된 파일은 **고급 제어 → 장치 내 미디어**에서 고를 수 있습니다. `39`에서도 로컬 파일을 선택할 수 있습니다. 먼저 `38`로 대상 파일을 생성하세요. 비어 있지 않은 최대 1 MiB 파일을 선택하면 Studio가 1 MiB 버퍼를 채우고 유효 길이와 마지막 블록 플래그를 설정합니다. `40`에는 기존 디렉터리를 사용하고 전송 후 `98`로 파일 크기를 확인하세요. `121`에서 배경 파일을 선택해도 장치 명령 화면에 머무릅니다. **미디어**를 열어 재생을 시작하세요. 로컬 JPEG와 PNG의 크기는 1~950,000바이트여야 합니다.

WinUSB 송수신 세션에는 명령 키가 필요합니다. 전송 전에 선택한 장치의 Studio 재생을 중지하세요. 전송할 때마다 요청을 한 번 보냅니다. `99`를 제외한 암호화 명령은 응답의 명령 번호와 최소 길이를 확인하며 이전 응답은 건너뜁니다. 요청은 재전송하지 않습니다. `99`는 텍스트 조각 하나를 표시합니다. 전체 목록은 **고급 제어 → 장치 내 미디어**에서 새로 고침한 후 완료 여부를 확인하세요.

Studio의 **장치 명령** 왼쪽 목록에서 명령을 선택합니다. 오른쪽에는 해당 명령에 필요한 입력란이 표시됩니다. 장치가 지원하고 매개 변수가 없는 명령은 바로 전송할 수 있습니다. 입력란이 화면에 다 들어오지 않으면 오른쪽 양식을 스크롤하세요. 오른쪽에서 명령 번호나 채널을 변경하면 일치하는 프리셋이 있을 때 왼쪽 목록에서 선택됩니다. 오른쪽 설명과 양식이 갱신되고 이전 명령의 매개 변수와 첨부 파일은 지워집니다. 번호는 10진수 또는 `0x`로 시작하는 16진수를 사용할 수 있습니다. 암호화 채널과 원시 채널의 번호는 독립적입니다. 예를 들어 암호화 채널의 `60`은 방향을, 원시 채널의 `0x60`은 온도를 조회합니다.

| 입력 또는 반환값 | 암호화 Win207 | 원시 채널 |
| --- | --- | --- |
| 명령 번호 | 0~255. 평문 헤더 오프셋 0에 기록 | 0~255. 요청 오프셋 0에 기록 |
| 매개 변수 | 평문 헤더 오프셋 8부터 0~492바이트. 나머지는 0으로 채움 | 오프셋 1부터 0~63바이트. 나머지는 0으로 채움 |
| 페이로드 | 선택 사항. USB 오프셋 512부터 추가. 길이, 플래그 등 헤더 필드는 명령표에 맞게 직접 채움 | 별도 페이로드 없이 요청 크기는 64바이트로 고정 |
| 반환값 | IN 엔드포인트에서 실제로 반환된 모든 바이트. 0을 유지하며 512바이트로 채우지 않음 | 왼쪽과 같음 |
| 응답 없음 또는 전송 실패 | 빈 응답이나 일부만 기록된 경우 I/O 오류로 보고. 드라이버 오류에는 작업 이름과 Windows 오류 코드가 포함됨 | 왼쪽과 같음 |

응답 화면에는 16진수 바이트 오프셋과 값, 인쇄 가능한 ASCII가 표시됩니다. 그 외 문자는 점으로 표시합니다. 응답 번호, 필드 오프셋 및 상태 값은 각 명령을 참고하세요. 동작 여부는 해당 장치 상태나 화면 출력에서 확인하세요.

| 예제 | 채널 및 번호 | 매개 변수 | 응답 |
| --- | --- | --- | --- |
| 펌웨어 조회 | 암호화 10 | 비움 | 응답 길이 ≥ 40바이트, 오프셋 0 = 10, 8–39 = UTF-8 버전 문자열 |
| H.264 블록 크기 조회 | 암호화 17 | 비움 | 응답 ≥ 12바이트, 8–11 = 빅 엔디언 블록 길이. 0은 기본값 |
| 장치 밝기를 60으로 설정 | 암호화 14 | `3C` | 공통 성공 코드는 정의되지 않음. 모델별 밝기 상한을 적용하려면 SDK의 `SetBrightness` 사용 |
| 냉각 온도 조회 | 원시 0x60 | 비움 | 응답 ≥ 3바이트, 1과 2 = 펌프와 팬 온도(°C) |

```csharp
byte[] firmware = screen.ExchangeCommand(10);
byte[] temperatures = screen.ExchangeRawCommand(0x60);
Console.WriteLine(Convert.ToHexString(firmware));
Console.WriteLine(Convert.ToHexString(temperatures));
```

명령 번호나 채널을 변경하면 입력란이 초기화됩니다. 명령을 선택한 뒤 매개 변수를 입력하세요. 입력란이 길면 요청 영역을 스크롤할 수 있으며 전송 버튼과 응답 영역은 아래에 표시됩니다.

**코드 예제**에서 생성한 코드는 장치를 열기 전에 모델과 요청 값의 범위를 확인합니다. 암호화 명령은 해당 응답을 받습니다. 디렉터리 조회 `99`는 디렉터리 데이터 한 조각을 반환합니다. 삭제 예제는 장치 인터페이스와 전체 파일 경로를 표시하며, `DELETE`를 입력해야 전송합니다.

## Windows 데스크톱 모드와 USB 보조 화면 모드

지원되는 화면에서 **장치 명령**으로 `150`을 보낸 다음 `11`을 별도로 보내 다시 시작합니다. `150`은 다음 부팅 모드를 설정합니다. 다시 시작하여 Windows 데스크톱 모드에 들어가면 WinUSB 인터페이스가 사라지고 데스크톱 모드 HID 인터페이스(`1A86:AD11`)가 나타납니다.

Studio에서 이미지와 동영상을 다시 보내려면 **장치 명령**의 왼쪽 목록에서 **USB보조화면으로 복귀**를 선택합니다. 이 HID 작업에는 Win207 명령 번호나 매개 변수 입력이 필요하지 않습니다. Studio의 USB 화면 목록이 비어 있어도 사용할 수 있습니다. 오른쪽 상세 패널에서 데스크톱 모드 장치를 새로 고침하고 일련번호로 장치를 선택한 다음 **USB보조화면으로 복귀**를 누릅니다. Studio는 HID 보고서를 한 번 보내고 동일한 일련번호의 WinUSB 인터페이스가 다시 나타날 때까지 최대 25초 기다립니다.

12.3인치 화면(`1CBE:0123`)의 명령 화면에서는 원시 채널과 암호화 명령 `12`, `51`, `52`, `61`, `62`, `125`, `251`, `252`가 비활성화됩니다. 백라이트를 끄려면 `14`에 10진수 `0`을 지정하여 전송합니다. 이 화면에서 `14`는 장치 값 0~80을, `13`은 `0`을 받습니다. 다른 방향은 **미디어**에서 선택하면 Studio가 프레임을 회전합니다.

표준 원형 디스플레이(PID `0021`)는 Windows 데스크톱 모드를 지원하지 않습니다. 원시 LED, 온도 및 속도 명령은 독립 컨트롤러 `0416:8061` 및 `0416:8052`용이며 Studio에 표시되는 `1CBE` 디스플레이에서는 사용할 수 없습니다. 암호화 번호 61과 62는 프로토콜 참조용입니다. 10진수 모드에서 0x61은 펌프와 팬 값을, 251은 펌프와 팬 3개의 값을 사용합니다. 252의 길이는 프레임 수, 간격 및 애니메이션 데이터를 포함합니다.

## 기본 제어 및 조회

| 번호 | 이름 | 매개 변수 및 응답 | Studio 화면 |
| --- | --- | --- | --- |
| 10 | GET_FIRMWARE_VERSION | 응답 0은 10이어야 하며 8–39는 UTF-8 펌웨어 버전. 끝의 NUL 제거 | 고급 제어 · 장치 명령 |
| 11 | RESTART_DEVICE | 헤더 매개 변수는 모두 0이며 요청은 512바이트. 다시 시작하면 USB 세션이 중단됨. 전용 성공 코드는 정의되지 않음 | 장치 명령 |
| 12 | SHUT_DOWN_DEVICE | 헤더 매개 변수는 모두 0이며 요청은 512바이트. 장치 종료를 요청함. 동작은 펌웨어에 따라 다름. 전용 성공 코드는 정의되지 않음 | 참조 |
| 13 | SET_DISPLAY_ORIENTATION | 헤더 8 = u8. 0~3은 0°, 90°, 180°, 270°에 대응하며 나머지는 0. Studio는 모델에 따라 호스트 프레임 회전과 펌웨어 방향 설정을 조합함. 결과는 실제 화면에서 확인해야 하며 일부 펌웨어에서는 명령 60의 응답에 설정이 반영되지 않음 | 미디어 · 방향 |
| 14 | SET_DISPLAY_BRIGHTNESS | 헤더 8은 0~100의 u8. Studio는 12.3인치 모델의 백분율을 floor(백분율 × 80 ÷ 100)로 변환함. 공통 성공 코드는 정의되지 않음 | 홈 · 디스플레이 제어 |
| 15 | SET_VIDEO_FRAME_RATE | 헤더 8 = u8, 단위는 초당 프레임. Studio는 1~60을 허용함. 첫 H.264 블록 쓰기 전에 설정 | 미디어, 실시간 입력 |

## 패킷 및 응답 예제

아래는 타임스탬프를 1 ms로 고정한 암호화 전 헤더입니다. 각 헤더를 0으로 500바이트까지 채운 다음 위 절차대로 암호화합니다.

| 작업 | 평문 헤더의 시작 바이트 | 설명 |
| --- | --- | --- |
| 버전 읽기 | `0A 00 1A 6D 01 00 00 00` | 10진수 10 = 0A. 모든 매개 변수는 0 |
| 밝기를 60으로 설정 | `0E 00 1A 6D 01 00 00 00 3C` | 오프셋 8의 3C는 10진수 60 |
| 180° 회전 | `0D 00 1A 6D 01 00 00 00 02` | 오프셋 8은 방향 코드 2 |
| 1024바이트 PNG 전송 | `66 00 1A 6D 01 00 00 00 00 00 04 00` | 길이는 빅 엔디언. 전체 USB 요청은 1536바이트 |
| 512바이트 H.264 마지막 블록 전송 | `79 00 1A 6D 01 00 00 00 00 00 02 00 01` | 오프셋 12는 마지막 블록 플래그 |

응답 디코딩 예제

- 17 응답의 8–11이 `00 03 18 00`이면 H.264 블록 길이는 202752바이트(198 KiB)입니다.
- 100 응답의 8–11이 `00 10 00 00`이면 SD 전체 용량은 4096 KiB입니다. 이 필드는 리틀 엔디언입니다.
- 원시 채널 온도 조회에서는 `60` 다음에 0으로 채운 63바이트를 보냅니다. 응답 오프셋 1과 2가 `23 28`이면 각각 35 °C와 40 °C입니다.
- 원시 채널 회전 속도 응답의 오프셋 1–4가 `06 D6 03 E8`이면 원시 값은 1750 및 1000입니다.

## 실행 예제

다음 CLI 명령은 소스 저장소 루트에서 실행합니다. 먼저 `list`로 장치 인덱스를 확인합니다. SDK ZIP에서 장치를 열거하려면 `dotnet run --project examples/SdkDiscover`를 실행합니다.

```powershell
dotnet run --project src/TURZX.WinUsbDisplay.Cli -- list
dotnet run --project src/TURZX.WinUsbDisplay.Cli -- info 0
dotnet run --project src/TURZX.WinUsbDisplay.Cli -- brightness 0 60
dotnet run --project src/TURZX.WinUsbDisplay.Cli -- image 0 artwork.png
dotnet run --project src/TURZX.WinUsbDisplay.Cli -- video 0 motion.mp4 24 --loop
dotnet run --project src/TURZX.WinUsbDisplay.Cli -- stop 0
```

SDK는 하나의 세션에서 여러 장치 메서드를 호출할 수 있습니다. 진단 메서드는 원시 응답을 반환하므로 위 표에 따라 해석하세요.

```csharp
using TURZX.WinUsbDisplay;

var devices = DisplayDevice.Discover(DisplaySettings.InterfaceGuid);
if (devices.Count == 0)
    throw new InvalidOperationException("No Win207 display found.");
using var screen = devices[0].Open(DisplaySettings.ReadCommandKey());
Console.WriteLine(screen.ReadFirmwareVersion());
screen.SetRotation(2);
byte[] status = screen.ReadDiagnostic(60);
if (status.Length >= 10)
    Console.WriteLine($"orientation {status[8]}, sensor {status[9]}");
byte[] temperatures = screen.ReadDiagnostic(0x60, raw: true);
```

참고 자료는 [Microsoft WinUSB 가이드](https://learn.microsoft.com/en-us/windows-hardware/drivers/usbcon/using-winusb-api-to-communicate-with-a-usb-device) 및 [FFmpeg 형식 문서](https://ffmpeg.org/ffmpeg-formats.html)를 확인하세요.

장치 제어 DLL을 직접 참조하는 프로젝트 설정과 전체 예제는 [DLL 개발 가이드](developer-guide.ko.md)를 참고하세요.
